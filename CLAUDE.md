# MapGame — AI Coding Instructions

## Project Context

- **Project:** "Путешествие по Европе" — a browser game where children learn European countries, flags and capitals.
- **Players:** two real kids, and the whole design follows from it — a 5 year old who cannot read, and an 11 year old who reads well. Every feature must work for both, usually by behaving differently per level.
- **Stack:** Vite, React 19, TypeScript, zustand, d3-geo + TopoJSON, Web Speech API, Web Audio API, vite-plugin-pwa.
- **No backend.** Everything is static; all state lives in `localStorage`. Never introduce a server, an account system or analytics.
- **Offline first.** The game is installed on a tablet and played without a network. Never add a runtime dependency on a remote asset or API.
- **Languages:** Russian, Polish, English — content and interface both. A string that only exists in one language is a bug.

### Commands

- `npm run dev` — local dev server on http://localhost:5173
- `npm run build` — production build into `dist/` (PWA, service worker, offline cache)
- `npm run data` — regenerate every derived data file, then validate. Run after touching `src/data/countries.json`.
- `npm run data:map` / `data:derived` / `data:flags` / `data:check` — the individual steps
- `npm run lint` — oxlint
- `npx tsc -b` — type check
- `SINGLE_FILE=1 npx vite build` — self-contained single-file build into `dist-single/`, for sharing the game as one HTML file
- `node scripts/build-icons.mjs` — redraw app icons from the map
- `node scripts/build-review-page.mjs out.html` — standalone page listing every country in all three languages, for proofreading
- `node scripts/build-artifact.mjs out.html` — turn the single-file build into a publishable page

## Core Concepts

### Data flows one way

`src/data/countries.json` is the only file a human edits. Everything else — the map, the zoom frames, the neighbour lists, the palette assignment, the flag files, the app icons — is generated from it by `npm run data`. If you need a new per-country fact, add the field to `countries.json` and to `types.ts`, then teach the validator about it.

### The validator is the contract

`scripts/validate-data.mjs` exits non-zero when a capital falls outside its own country's polygon, a translation is missing, a flag file does not exist, a country references a symbol nobody drew, or two bordering countries got the same map colour. Extend it whenever you add data. A silent data bug is far worse here than a crash — it teaches a child something wrong.

### Two levels, not one difficulty slider

`PRESETS` in `src/game/types.ts` is where the two children are encoded: number of options, round length, whether text is shown, whether capitals are included, how distractors are chosen, and which fame tier of countries is in play. The gap between a 5 and an 11 year old is too wide for one knob. When adding a feature, decide what it does at each level.

### The flag round runs backwards for the little one

An unreadable child cannot pick a country name from a list. When `preset.showText` is false, the flag mode inverts: the country is spoken aloud and the answers are flags. This lives in `GameScreen` as `flagsAsAnswers`.

### Spaced repetition, not random

`src/game/questions.ts` keeps a per-country `streak` and `dueAt`. A miss brings a country back within three questions; each correct answer pushes it further out (3, 8, 20, 45, 90). Rounds work off a local copy of that memory so repeats are scheduled within a single round too.

### Mistakes never punish

There is no score penalty, no red cross, no failure sound. A wrong answer reveals the right one on the map, names it aloud, and schedules it to come back. On the map round only, one wrong tap lights up the neighbourhood as a hint before the answer is shown.

### The map is an atlas for children, not a data visualisation

The borders are real Natural Earth geometry, but everything around them is
drawn to read as a picture book: a flat offset shadow under the land so the
countries look like paper stickers, four pastel fills assigned so no two
neighbours match, and `SeaDecor` — a compass rose, a boat, a whale and wave
ticks placed at real open-sea coordinates. The decoration lives inside the
zoom transform so it drifts with the map, is `pointer-events: none` so it can
never swallow a tap meant for a country, and hides itself past 3x zoom.

### Microstates are markers, not polygons

Seven countries (AD, LI, LU, MT, MC, SM, VA) are too small to tap at map scale. They are flagged `micro: true` and drawn as fixed-size markers with a 16px hit circle, which disappear once the zoom makes the real shape tappable. The Vatican has no polygon at all at our quantization and exists only as a marker.

## Common Patterns

- **Adding a country** — add the entry to `countries.json` (all three languages, `fame`, `micro`, `symbol`, capital coordinates as `[lon, lat]`), then `npm run data`. The validator tells you what is missing.
- **Adding a drawn symbol** — add an entry to `SYMBOLS` in `src/ui/symbols.tsx` (64×64 viewBox, flat three-or-four-colour style), reference it from `countries.json`. Check it at `#symbols`, which renders every symbol beside its country.
- **Adding an interface string** — add the key to `STRINGS` in `src/i18n/ui.ts` with all three languages; `t(key, lang)` is typed against it.
- **Speaking text** — `speak(text, lang)` from `src/speech.ts`; guard with `canSpeak(lang)`, because a device may have no voice for a language.
- **Playing a sound** — `sounds.correct()` and friends from `src/sound.ts`. Sounds are synthesised, never loaded from files.
- **Showing the map** — `<WorldMap>` takes `correct`, `wrong`, `highlight`, `spotlight`, `focus`, `capital` and `onPick`. `focus` animates the zoom; `highlight` marks the country a question is about, in a colour deliberately different from the correct-answer green.

## Anti-patterns & Gotchas

### Do NOT edit the generated data files

`europe.topo.json` and `derived.json` are outputs. Edit `countries.json` or the generating script, then rerun `npm run data`.

### Do NOT fit a conic projection to a rectangle

`geoConicConformal().fitSize()` on a four-corner polygon sends the projection through its own singularity and collapses the scale to about 0.001 — the map renders as a single dot. Fit to a grid of `MultiPoint` coordinates instead. See `createProjection` in `src/map/projection.ts`.

### Do NOT simplify the map geometry

`topojson-simplify` flattens small islands into degenerate rings, and d3-geo then reads a degenerate ring as covering the entire sphere — Germany's bounding box becomes the whole world. Quantization alone causes it too, which is why `build-map.mjs` cleans collapsed rings and fixes ring winding after quantizing, and repeats until nothing else collapses. Do not remove that pass.

### Do NOT show a country's flag next to its capital in the answers

It hands the answer to any child who knows flags. The flag of the country being asked about belongs in the question, never on the options.

### Do NOT build sentences that decline a country name

"Столица страны Германия?" and "Stolica kraju Niemcy?" are both wrong — Russian and Polish need genitive forms the data does not have. Show the country name on its own line and ask a standalone question under it.

### Do NOT import the flag-icons stylesheet

It pulls all ~250 world flags into the bundle. `build-flags.mjs` copies only the 45 in use, and `Flag.tsx` loads them through `import.meta.glob`.

### Do NOT let map callbacks change identity every frame

`useMapView` mirrors the current view in a ref so `focusBox`, `reset` and `animate` stay referentially stable. If they change on each animation frame, the effect that starts a zoom restarts it forever and the map never returns from a focused country.

### Do NOT grey out the map to highlight an answer

The bright green with a dark edge is enough. Dimming every other country removes exactly the context a child needs to see where the country is.

### Do NOT zoom all the way in on a small country

`focusBox` takes a max scale for this reason. A country filling the whole screen tells a child nothing about where in Europe it sits.

### Do NOT use emoji for interface icons

They render differently on every device and platform. Draw an SVG instead — see `ModeIcon`, `Kid`, `CountrySymbol`. Emoji *artwork* checked into the repo as an SVG file is fine and renders identically everywhere: `src/assets/art/plane.svg` is Noto Emoji art under Apache 2.0. Anything added that way needs an entry in `src/assets/art/NOTICE.md`, and the licence must not be share-alike.

### Do NOT add a dark theme

The game is deliberately single-theme and light: pastel countries on a dark ground look muddy, and the audience does not need it. `--color-scheme: light` is set on purpose.

### Do NOT put a language or profile setting on the start screen beyond the flags

The start screen belongs to the child: two characters and three flags, nothing else to read. Grown-up settings live in the menu behind the character.

### Mind the Web Audio autoplay policy

`AudioContext` cannot start before a user gesture. `src/sound.ts` creates it lazily on the first sound and resumes a suspended context. Do not construct it at module load.

### Mind the missing voices

Web Speech voices are per-device. Polish in particular is missing on many systems. Always gate speech UI behind `canSpeak(lang)` rather than assuming it works.

### Comments in code are English, always

Regardless of the language used in chat or in the data. Write them to explain why, not what.
